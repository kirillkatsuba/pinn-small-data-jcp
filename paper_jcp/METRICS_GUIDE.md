# Метрики, их интерпретация и правила отбора результатов

Этот документ фиксирует, как интерпретировать все столбцы итоговых CSV
унифицированного протокола и какие из них являются основными для статьи JCP.
Он относится к итоговым наборам результатов:

- `generated/test1_corrected_candidate/unified_test1.csv`;
- `generated/corrected_test2_final/unified_test2.csv` вместе с усиленным
  подбором classical baselines из `generated/corrected_test2_classical_strong/`;
- `generated/corrected_test3_final/unified_test3.csv`;
- `generated/corrected_test4_final/unified_test4.csv`.

Во всех окончательных тестах используются бюджеты меток
`N = 20, 50, 100, 200, 500, 1000`, три seed (`101`, `102`, `103`) и два
непересекающихся режима оценки: `interpolation` и `extrapolation`.
В статье каждая итоговая величина должна приводиться как **mean +/- std по
трём seed**, а не как лучший единичный запуск.

## 1. Что является главным результатом

### Tests 2--4: water saturation

**Главная метрика статьи: `Swat_R2`**. Это коэффициент детерминации для
water saturation `S_w`; он измеряет долю вариации истинного поля насыщенности,
объяснённую предсказанием:

`R2 = 1 - sum_i (y_i - yhat_i)^2 / sum_i (y_i - ybar)^2`.

- Больше — лучше.
- `R2 = 1` означает точное предсказание на оцениваемом наборе.
- `R2 = 0` соответствует предсказанию константой, равной среднему truth.
- `R2 < 0` означает, что метод хуже такого константного baseline.

Именно `Swat_R2` нужно использовать в главных таблицах и на центральных
кривых «точность -- число меток». Water saturation является наиболее сложным
и физически содержательным выходом: она определяет фронт вытеснения и сильнее
всего страдает от недостатка данных и временной экстраполяции.

Для каждого `N` следует показывать два значения: отдельно внутри временного
интервала обучения (`interpolation`) и после его правой границы
(`extrapolation`). Второе важнее для основного тезиса о физически
информированном прогнозе.

### Test 1: heat equation

В Test 1 сеть имеет один скалярный выход, поэтому основной показатель имеет
имя просто **`R2`**. Его смысл полностью тот же, что у `Swat_R2`.

### Как определить наилучший метод

1. Внутри одного теста, бюджета и режима оценки наилучшим считается метод с
   максимальным средним `R2`.
2. Когда разность средних сравнима со стандартным отклонением трёх seed,
   результат следует описывать как сопоставимый, а не как безусловную победу.
3. Основной тезис проверяется прежде всего при `N=20, 50, 100, 200`; результаты
   при `N=500, 1000` показывают, как преимущество меняется при насыщении данными.
4. Нельзя заменять среднее по seed одним лучшим запуском.

## 2. Метрики ошибки для каждого поля

В Tests 2--4 предсказываются `Pressure`, `Soil` и `Swat`. Для каждого из них
записываются одинаковые четыре метрики.

| Столбцы | Формула / смысл | Направление | Роль в статье |
|---|---|---:|---|
| `*_MSE` | `mean((y - yhat)^2)` | меньше | Вспомогательная; чувствительна к крупным ошибкам. |
| `*_RMSE` | `sqrt(MSE)` | меньше | Основная абсолютная ошибка в физических единицах поля. |
| `*_MAE` | `mean(abs(y - yhat))` | меньше | Робастная абсолютная ошибка; полезна как проверка, что результат не создаётся несколькими выбросами. |
| `*_R2` | коэффициент детерминации | больше | **Главная сравнительная метрика.** |

Префиксы означают:

- `Pressure_*` — давление;
- `Soil_*` — oil saturation `S_o`;
- `Swat_*` — water saturation `S_w`.

### Почему не следует делать главным `Pressure_R2`

Давление на этих тестах существенно проще: почти все методы достигают очень
высокого `Pressure_R2`. Усреднение с давлением способно скрыть плохое качество
фронта насыщенности. Поэтому давление нужно показать как подтверждающую
метрику, а `Swat_R2` — вынести в основной текст.

### `Soil` и условие замыкания

В физической постановке насыщенности должны удовлетворять `S_o + S_w = 1`.
Поэтому метрики `Soil_*` во многом согласованы с `Swat_*`, но не являются
полностью избыточными: сеть может нарушать замыкание. Для этой проверки есть
отдельная `closure_MAE`.

## 3. Усреднённые метрики нескольких выходов

| Столбец | Определение | Использование |
|---|---|---|
| `mean_MSE` | среднее `MSE` по Pressure, Soil, Swat | Вторичная сводка. |
| `mean_RMSE` | среднее `RMSE` по трём полям | Вторичная сводка. |
| `mean_MAE` | среднее `MAE` по трём полям | Вторичная сводка. |
| `mean_R2` | среднее трёх `R2` | Удобен для общей картины, но не заменяет `Swat_R2`. |

Эти четыре столбца нельзя использовать как единственное доказательство
small-data тезиса: лёгкое давление может искусственно завысить `mean_R2`.

## 4. Безразмерные ошибки

| Столбец | Определение | Направление | Роль |
|---|---|---:|---|
| `*_relative_L2` | `||y-yhat||_2 / (||y||_2 + 1e-12)` | меньше | Сравнение относительной ошибки между полями различного масштаба. |
| `*_NRMSE_std` | `RMSE / (std(y) + 1e-12)` | меньше | Ошибка в единицах стандартного отклонения truth. |
| `mean_relative_L2` | среднее `relative_L2` по трём выходам | меньше | Вторичная общая характеристика. |
| `mean_NRMSE_std` | среднее `NRMSE_std` по трём выходам | меньше | Вторичная общая характеристика. |

Для Test 1 доступны скалярные `relative_L2` и `NRMSE_std` без префикса.

Эти показатели особенно полезны в supplementary table или при сравнении тестов
между собой. В основной таблице предпочтительнее `Swat_R2` вместе со
`Swat_RMSE`.

## 5. Физическая правдоподобность предсказания

Эти метрики есть для Tests 2--4.

| Столбец | Определение | Лучшее значение | Почему важно |
|---|---|---:|---|
| `saturation_bounds_violation` | Доля точек, где `S_o` или `S_w` выходит за `[-1e-3, 1+1e-3]` | 0 | Проверка физических границ насыщенности. |
| `closure_MAE` | `mean(abs(Soil_hat + Swat_hat - 1))` | 0 | Проверка условия `S_o + S_w = 1`. |

Их следует приводить для PINN в таблице физической валидации. Низкий `R2` не
может компенсироваться хорошим closure, но хорошая точность насыщенности вместе
с близкими к нулю `closure_MAE` и `saturation_bounds_violation` делает результат
физически убедительным.

## 6. Метаданные протокола и вычислительная стоимость

| Столбец | Смысл |
|---|---|
| `n_train` | Число размеченных data points `N`. |
| `n_collocation_per_epoch` | Число PDE residual points `N_r` в одной эпохе PINN. |
| `seed` | Seed конкретного независимого запуска. |
| `evaluation_region` | `interpolation` либо `extrapolation`. |
| `label_time_fraction`, `time_cutoff`, `full_time` | Разделение времени обучения и прогнозирования. |
| `n_test` | Число точек финальной оценки. |
| `train_time_sec` | Время обучения/подбора модели в секундах; меньше — лучше. |
| `model_*`, `balancer`, `optimizer`, `scheduler`, `learning_rate`, `l0_data`, `l0_ibc` | Зафиксированная конфигурация PINN. |
| `classical_tuning_profile`, `classical_cv`, `classical_tuning_details_json` | Аудит честности настройки XGB/SVM/GP. |

`train_time_sec` нужно показывать отдельно от точности. Он фиксирует честный
trade-off: PINN в нашем протоколе дороже classical surrogates, но выигрывает в
data-limited реконструкции насыщенности и в экстраполяции.

## 7. Рекомендуемый набор таблиц и рисунков JCP

1. **Главная таблица:** `Swat_R2 (mean +/- std)` для H-PINN, HO-PINN, XGB,
   SVM и GP; Tests 2--4; `N=20, 50, 100, 200`; interpolation и extrapolation.
2. **Основной рисунок:** кривые `Swat_R2` относительно `N` с error bars;
   отдельные панели для Tests 2--4 и отдельно для interpolation/extrapolation.
3. **Таблица физических свойств:** `Swat_RMSE`, `closure_MAE`,
   `saturation_bounds_violation` и `train_time_sec` для representative budgets
   `N=20` и `N=200`.
4. **Качественные поля:** pressure, `S_w`, `S_o` в нескольких моментах времени;
   truth, PINN prediction и absolute error на одной шкале цветов.
5. **Test 1:** одна компактная таблица scalar `R2` и рисунок решения heat
   equation в последовательные моменты времени.

## 8. Текущий содержательный вывод

Наиболее сильный и аккуратный тезис, поддерживаемый метриками:

> При известной PDE-модели и малом числе размеченных наблюдений H-PINN/HO-PINN
> дают существенно более точное восстановление water saturation, особенно при
> временной экстраполяции, чем тщательно настроенные XGB, SVM и Gaussian Process.

Утверждение не должно звучать как «PINN всегда лучше»: в Test 3 при
`N=500--1000` GP немного превосходит PINN в **интерполяции**, тогда как PINN
сохраняет преимущество в экстраполяции. Именно эта граница применимости делает
вывод правдоподобным и научно содержательным.

## 9. Визуализация reference решений

### Tests 2--4: pressure и насыщенности

`plot_corrected_flow_data.py` уже строит три готовых рисунка из FV reference
solution: двумерные поля `Pressure`, `Swat`, `Soil`; усреднённые по `y`
профили по `x`; а также временные кривые средней и максимальной water
saturation. Для Test 4 один `.npz` файл соответствует одному набору четырёх
параметров относительных проницаемостей.

```bash
cd /path/to/pinn-small-data-jcp

python3 -B paper_jcp/plot_corrected_flow_data.py \
  --input paper_jcp/generated/corrected_final/test2/solution.npz \
  --time-fractions 0,0.02,0.05,0.1,0.25,0.5,0.7,1

python3 -B paper_jcp/plot_corrected_flow_data.py \
  --input paper_jcp/generated/corrected_horizon_pilots/test3/solution.npz \
  --time-fractions 0,0.02,0.05,0.1,0.25,0.5,0.7,1

python3 -B paper_jcp/plot_corrected_flow_data.py \
  --input paper_jcp/generated/test4_horizon_02/test4/sample_000.npz \
  --time-fractions 0,0.02,0.05,0.1,0.25,0.5,0.7,1
```

По умолчанию результаты сохраняются рядом с `.npz` в каталоге
`<имя файла>_figures/`: `fields.png`, `profiles.png`, `time_series.png`.
Чтобы отрисовать другой параметрический сценарий Test 4, замените
`sample_000.npz` на, например, `sample_025.npz`.

### Test 1: точное решение heat equation

`plot_test1_exact_solution.py` строит профили точного решения в выбранные
моменты времени и heatmap `u(t,x)`:

```bash
cd /path/to/pinn-small-data-jcp

python3 -B paper_jcp/plot_test1_exact_solution.py \
  --time-fractions 0,0.02,0.05,0.1,0.25,0.5,0.7,1 \
  --output paper_jcp/figures/test1_exact_solution.png
```

Эти скрипты визуализируют **reference solutions**. Для figure уровня статьи
наиболее ценной следующей визуализацией будет панель `truth / PINN prediction /
absolute error` на одном и том же временном срезе; её следует строить из
сохранённого checkpoint финального H-PINN или HO-PINN, а не из одного только
CSV с метриками.
